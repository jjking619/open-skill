# 文档一致性审计（Documentation Consistency Audit）

把「一批文档 / 多语言镜像文档到底有没有对齐」变成**可复现的检查 + 可复核的报告**：
先机械层扫描（脚本能查的绝不靠肉眼），再语义层抽查，最后按严重级出报告。

## 何时使用（When to Use）

- 一批文档（一个目录树、一个知识库、一个产品线）交付前检查
- 中英（或多语言）镜像文档树：确认两侧是否同步、是否漏译
- 版本发布前的文档回归：占位行、TODO、失效链接、命令块错误
- 不适用：单篇润色（直接改更快）；产品文案审稿

## 前置（Prerequisites）

- 明确**检查范围**与**镜像关系**（哪些文档是同一内容的不同语言版本）
- 拿到文档源（本地 md / 仓库 / 平台 API 均可，机械层只依赖纯文本）

## 流程（Procedure）

**① 定范围与镜像对**
列出待查清单；建立「中文 ↔ 英文」配对表（按路径或标题指纹配对，**不要靠标题字面**——镜像标题是译文）。配对方式写进报告开头。

**② 机械层扫描（可脚本化，优先做）**
逐项用正则/解析器查，命中即给「文件 + 行号 + 片段」：
- 链接：URL 里的空格与未编码字符、锚点是否存在、相对路径是否有效、`http(s)` 是否可访问
- 代码块：shell 命令与注释粘连、多条命令挤在一行、缺语言标注、围栏未配对
- 占位残留：修订记录里的 `-` / `TBD` / `TODO` / `xxxx`、模板字段未替换
- 术语变体：同一专有名词的多种写法（含全半角、大小写、空格差异）
- 版式：标题层级跳跃（h2 → h4）、表格列数不齐、空标题

**③ 语义层抽查（机械层查不到的）**
- 结构与宣称是否一致：目录/功能清单里提到的模块，正文是否都有对应章节（漏章、多章）
- 数字与配置一致：文档里的阈值、版本号、参数名与配置文件/实际输出一致
- 镜像一致性：两侧章节数、代码块数、表格数、图片数是否相当；缺失的段落标出来
- 图文对应：图片是否都有说明、图注与正文是否指同一对象

**④ 结果落成 findings**
每条一条记录：`文件 | 位置 | 问题类型 | 证据片段 | 严重级 | 建议`。
问题类型归一化（枚举见附录），便于统计与批量修复。

**⑤ 出报告**
按附录给出的报告骨架成稿：一句话结论 → 按严重级分组（🔴 阻断 / 🟡 需修 / 💡 建议）→ 每类问题给「可 Ctrl+F 定位的短片段 + 数量」→ 附录给镜像配对表与扫描口径。

## 修复纪律（Fix Discipline）

- **确定性问题直接修**：错别字、链接编码、占位行、命令粘连这类没有歧义的，边审边改，不必逐条请示。
- **镜像同步**：改了中文版，必须同步检查/修改对应英文版（反之亦然）。
- **语义/需确认的列出来**：疑似错但不确定的、需要业务判断的，不擅自改，进报告「待确认」。
- **改完留痕**：报告里区分「已修正」与「待处理」，并记录修正位置。

## 坑（Pitfalls）

- **镜像文档不能按标题字面配对**：标题是译文，要用路径或内容指纹配对。
- **只扫不读会漏语义问题**：机械层只管可模式化的；漏章、数字不符、图文错配只能抽查。
- **一次改太多导致 diff 不可读**：确定性问题直接改，但把「结构重排」类改动与「字词修正」分开处理。
- **把「风格差异」当问题报**：没有既定风格约定的写法差异，最多算 💡 建议，别当阻断项。

## 验收（Verification）

- [ ] 报告开头写明范围、口径、镜像配对方式
- [ ] 每条问题都有「文件 + 位置 + 可定位片段」，第三方能直接复现
- [ ] 已修正项与待确认项分开列，数量与清单一致
- [ ] 镜像文档两侧都过了一遍（不是只查一侧）
- [ ] 报告里没有「建议优化」这类无落点的条目

## 附录：检查清单与报告骨架

### 六类检查项

| 类别 | 检查项 |
|---|---|
| 结构 | 宣称 vs 实际（目录/功能清单提到的模块是否有对应章节）、漏章与多章、标题层级不跳级、空标题/空章节、手动编号连续 |
| 链接 | URL 里的空格与未编码字符、锚点是否存在、相对路径是否有效、外链可达（HTTP 2xx/3xx）、链接重复定义 |
| 代码块 | 命令与注释粘连、多条命令挤一行、缺语言标注、围栏配对、提示符残留（`$ ` `> ` `PS> `）、命令与输出混写 |
| 占位残留 | 修订记录里的 `-` / `TBD` / `TODO` / `xxxx`、模板字段未替换 |
| 术语与写法 | 专有名词只有一种写法、全半角与大小写统一、中英混排空格按既定策略统一、缩写首次出现给全称、单位格式（`5V` vs `5 V`） |
| 版式 | 表格每行列数 = 表头列数、每表有分隔行、图片有说明、列表嵌套一致 |
| 镜像一致 | 配对完整（每个语言版本都能配到对侧）、章节数相当、代码块/表格数相当、关键段落内容指纹两侧都在、链接对称 |

### 问题类型归一化枚举

`structure-missing` · `structure-extra` · `heading-level` · `empty-section` · `link-encoding` · `link-anchor` · `link-dead` · `code-glue` · `code-lang` · `code-fence` · `term-variant` · `spacing` · `unit-format` · `table-shape` · `placeholder-leftover` · `mirror-missing` · `mirror-mismatch`

每条 finding 记录：`文档 | 位置 | 类型 | 证据片段（约 20 字符上下文） | 严重级 | 建议`。

### 报告骨架

```
# <范围> 文档一致性审计报告
> 审计日期 | 范围（篇数）| 口径：机械层全量 + 语义层抽查 | 镜像配对方式 | 未配对 N 篇

## 一句话结论（可放行 / N 处需先修 / N 处阻断；已直接修正 M 处、待确认 K 处）
## 一、已直接修正        表格：# | 文档 | 位置 | 类型 | 改前 → 改后
## 二、待处理（按严重级）  🔴 阻断 / 🟡 需修 / 💡 建议，表格：文档 | 位置 | 类型 | 证据片段 | 建议
## 三、统计             按类型计数（类型 | 数量 | 涉及文档数）
## 四、镜像对齐情况      中文文档 | 英文文档 | 章节数 | 代码块 | 表格 | 结论（对齐/缺段/未配对）
## 附录                扫描口径与命令 / 未配对文档清单 / 未覆盖内容（无权限、需业务确认）
```

严重级定义：🔴 阻断（功能或事实错误）· 🟡 需修（一致性/可读性）· 💡 建议（风格偏好，可不改）。
