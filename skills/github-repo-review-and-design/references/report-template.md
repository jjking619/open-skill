# 整仓审查报告模板

输出到终端或落 md 文件。两档模式二选一：**评估档**（第三方只读）/ **发布档**（自家可整改）。
报告语言跟随对话语言（默认中文）；发现条目格式统一，便于直接转 issue/PR 评论。

---

## 报告头

- 仓库：`owner/repo` @ `commit短SHA`
- 审查模式：评估档（第三方）/ 发布档（自有）
- 规模速览：语言 / 文件数 / LOC / 最近提交日期 / 是否 archived / 许可证声明
- 一句话结论

---

## 评估档（第三方）— 结论卡

| 维度 | 结论 | 证据（文件/现象） |
|------|------|------|
| 维护活跃度 | 🟢🟡🔴 | 近一年提交数、最近提交日期、issue 响应 |
| 代码质量 | | L1/L2 抽样观感、死代码/复杂度 |
| 文档与上手成本 | | README 可复现性、示例完整度 |
| 依赖与许可风险 | | 漏洞审计、LICENSE 一致性 |
| 安全面 | | 敏感信息/注入面扫描结果 |
| 生态 | | star/forks/替代品对比 |

**采用建议**：
- ✅ 直接用（理由 + 建议锁定的版本/commit）
- 🔶 参考学习（摘出值得借鉴的模块/写法清单）
- ❌ 放弃（理由：不维护/许可不合规/质量差/有更好替代）

---

## 发布档（自有）— 发布就绪检查表

- [ ] 敏感信息清零：密钥/口令/私钥/内网 IP/个人路径，**含历史 commit 与测试目录**
- [ ] LICENSE 与文件头/README 声明一致；依赖许可证清单无冲突
- [ ] README：描述/安装/快速开始/配置说明/FAQ/截图齐备，**命令照着跑能通**
- [ ] .gitignore 覆盖运行产物；无大文件/模型误入库（>10MB 逐项说明去向）
- [ ] 测试可跑且绿（或说明无测试的取舍）；CI（如有）真实在跑
- [ ] 版本号/CHANGELOG/tag 策略明确
- [ ] 入口一致性：教程命令 == 真实入口（出厂终端直跑验证）
- [ ] 贡献指南/issue 模板（如计划收贡献）

**就绪度**：🟢 可发布 / 🟡 修完下列 N 项后可发布 / 🔴 未就绪

## 发现明细

### 🔴 阻断级（必须修）
- `path/to/file.py:45` — 问题一句话。建议：…。
- …

### 🟡 警告级（应该修）
- `path/to/file.py:23` — 问题一句话。建议：…。
- …

### 💡 建议级（可选）
- `path/to/file.py:8` — 问题一句话。建议：…。
- …

### ✅ 亮点（值得保留/学习）
- 模块划分清晰、错误处理到位、README 图例齐全等具体现象。

（路径一律相对仓库根；同一文件多处问题合并条目。）
