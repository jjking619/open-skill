# 同步任意 md 到「用户指定的已有飞书文档」（非检查报告场景）

用户丢一个 wiki/docx 链接 + 「同步到这里 / 写进这篇」时的链路。
与报告发布链路的区别：**不建新节点、不改节点名**，按用户给的容器原地写入。
（介绍稿、方案说明、汇报稿等非报告类 md 都走这条。）

## 步骤

1. **解析目标容器**
   - wiki 链接 `.../wiki/<node_token>`：`GET /wiki/v2/spaces/get_node?token=<node_token>`
     → `data.node.obj_token`（= docx document_id，写块用它）。**wiki token ≠ doc_id，必须先解析**。
   - docx 链接 `.../docx/<doc_id>`：直接用。
2. **先读现状**：`GET /docx/v1/documents/{doc_id}/blocks?page_size=100&document_revision_id=-1`
   确认是空白文档还是已有内容。`--doc` 是「清空全部子块再重写」——**目标已有内容时先跟用户确认可覆盖**。
3. **权限**（首次落地几乎必经）：无权限时 `131006 node permission denied` →
   让用户在文档「分享」面板把机器人应用加成**可编辑**，
   或把应用加为该知识库空间成员。**用户授权后立即生效，直接重试即可**，不必换链接或新建文档。
   - ⚠️ **别用 `GET /wiki/v2/spaces` 返回空判定「用不了」**：本应用该接口返回 `items: []`，
     但节点级授权后读写正常。以 `get_node` 的返回码为准，不做提前否定。
4. **写入**：`<发布脚本> <md> --doc <obj_token>`
   - 先清空该文档全部子块，再按 md 重写；**URL 不变、幂等**，可反复重发（改了稿子就重发，不用换链接）。
   - **节点标题不改**（保留用户自己设的标题）；md 的 H1 只成为文档内第一个标题块。
   - 不写台账类表格（这类文档不是审查产物）。
   - 长任务纪律：`background=true` + `notify_on_complete`；一次调用只发一篇。
   - 脚本实现不在本技能内；按 md 解析块 → 清空目标文档子块 → 重写即可。
5. **写后核对（必做）**：分页拉 blocks（按 `has_more` 循环，别把单页 500 当成总数）→
   - 表格块数（`block_type == 31`）**必须等于** md 里 `|---|---|` 分隔行数；
   - 顶层块末块不应停在表格上；
   - 顶层块数 = 写入内容块数 + 表格数。
   核对通过再向用户汇报；报告里用「已回读云端核对，非脚本自述」的口径。

## 渲染支持

md → 飞书块的语法支持矩阵、表格 9 行上限与列宽计算、单元格改写方式：见 `report-md-to-wiki.md`。
本类稿子常用（标题 1-4 级 / 引用 / 待办 / 有序-无序列表 / 分隔线 / 代码块 / 超链接 / 表格）都在支持范围内，
表格 ≤9 行时不会触发拆表。

## 实测（2026-09-28）

- 场景：用户给 wiki 链接 + 「直接同步到我的飞书云文档」。
- 首调 `get_node` 返回 131006 → 告知用户加应用为可编辑 → 用户授权后**重试一次即通过**。
- 目标是空白 docx（先 `get_node` 解析出 obj_token）。
- 结果：112 内容块 + 7 表格 = 119 顶层块（含单元格共 288 块）；云端表格 7 == 本地 md 分隔行 7；
  顶层末块为 todo（附录待填清单）→ 判定完整，无半截状态。
